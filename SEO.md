# SEO & search — how this site is set up and what to do after deploy

This is the operator's guide for `noiceanas.com` search presence. The code changes
are done; the steps below are the **manual actions only you can do** (GitHub
settings + Google Search Console) plus context on what to realistically expect.

---

## 1. What stack am I on now?

Still **vanilla static HTML / CSS / JS on GitHub Pages** — same family as the old
MyWebsite, not a framework. What changed vs. the old site:

- It's a **single page** with CSS tab-toggling (About/Skills/Projects/Resume/Contact
  are all in one `index.html`, shown one at a time). All that content is in the
  static DOM, so **it's fully crawlable** — the single-page structure is *not*
  hurting your English SEO.
- There's now **one tiny build step** (`npm run build`) that generates a real static
  Arabic page, `index-ar.html`, from the translation dictionary. That's the only
  moving part beyond plain files. See `CLAUDE.md` → *Build & i18n architecture*.
- Deploy is now a **GitHub Actions pipeline** (`.github/workflows/deploy.yml`) instead
  of "deploy from branch," so the Arabic page is rebuilt fresh on every push.

**The one real SEO regression from the old site — now fixed:** the old MyWebsite had
Arabic text sitting directly in `index-ar.html`, so Google indexed it and ranked it.
The new site renders Arabic with JavaScript *after* load, so crawlers only saw
English → the Arabic result started dying and `/index-ar` 404'd. The build step
restores a genuine Arabic HTML page at that exact URL.

## 2. Required one-time setup after this ships

> ⚠️ **The Pages-source switch (step A) is the single prerequisite the whole fix
> hangs on.** `index-ar.html` is generated by CI, not committed. If Pages is still
> on "Deploy from a branch" when this merges, `/index-ar` will 404 — but the new
> `sitemap.xml` and `hreflang` now *point search engines at that URL*, which is
> **worse than today**. So the order is non-negotiable:
> **flip the setting → confirm the Actions run is green → open `https://noiceanas.com/index-ar`
> live → only THEN do the Search Console steps in §3.** Never re-index before
> `/index-ar` resolves live.

**A. Switch Pages to build via Actions.**
GitHub → repo → **Settings → Pages → Build and deployment → Source → "GitHub
Actions"** (currently "Deploy from a branch"). Without this, the workflow builds but
nothing deploys. The custom domain (`noiceanas.com`, via `CNAME`) carries over — no
DNS change.

**B. Confirm the first deploy.**
After merging to `main`, watch the **Actions** tab for a green run, then check:
- `https://noiceanas.com/` loads (English).
- `https://noiceanas.com/index-ar` loads (Arabic, RTL) — this is the reclaimed URL.
- `https://noiceanas.com/does-not-exist` shows the branded **404** (not GitHub's).
- `view-source:https://noiceanas.com/index-ar` shows **Arabic text in the raw HTML**
  (Ctrl-F for `مهندس`). If it's there, Google will index Arabic. This is the whole point.

## 3. Google Search Console (do this once the site is live)

1. **Verify the property** for `noiceanas.com` (domain property, DNS TXT record) if
   not already — https://search.google.com/search-console.
2. **Submit the sitemap:** Sitemaps → add `sitemap.xml`. It lists `/` and `/index-ar`
   with `hreflang`.
3. **Request indexing** for the two canonical URLs: URL Inspection → paste
   `https://noiceanas.com/` → *Request indexing*. Repeat for
   `https://noiceanas.com/index-ar`.
4. **The stale `/index-ar` 404 heals itself** — because that URL now returns a real
   page, Google drops the 404 on its next crawl. **Do NOT use the Removals tool** on
   it (that would hide the new page too). Just let the re-crawl happen; requesting
   indexing in step 3 speeds it up.
5. **Rich result check** (optional): run `https://noiceanas.com/` through
   https://search.google.com/test/rich-results to confirm the `Person` structured
   data is picked up. This is what can produce a knowledge-panel-style card for your
   name.
6. Give it **days to a few weeks** — crawling isn't instant. Watch Search Console →
   Pages / Performance for `/index-ar` moving from "not indexed" to "indexed."

## 4. Retire the old MyWebsite from search (important — it competes with you)

`https://noice-anas.github.io/MyWebsite/` is a **different repo** (`Noice-Anas/MyWebsite`,
archived) that is very likely **still indexed** — an old page about the same person,
competing with your real site and possibly still showing the old `/index-ar`. Do one
of these **in that repo** (not this one):

- **Best — redirect it.** Add a `<meta http-equiv="refresh" content="0; url=https://noiceanas.com/">`
  and a `<link rel="canonical" href="https://noiceanas.com/">` to its pages so all
  signals consolidate onto `noiceanas.com`. (Unarchive to edit, or leave archived and
  just accept option below.)
- **Simplest — de-index it.** Add `<meta name="robots" content="noindex">` to its
  `index.html` / `index-ar.html`, or a `robots.txt` disallow. It drops out of search
  over the next few crawls.
- Then in **that site's** Search Console property, submit the change / request
  removal of its outdated URLs.

Until this is done, searches for your name may surface the old github.io page.

## 5. What "better SEO" realistically gets you

**In your control (all done in code now):** clean titles/descriptions, canonical,
`hreflang` EN↔AR, a real Arabic page, JSON-LD `Person`, sitemap, a proper 404, fast
static load. This makes the **result for your name** correct, rich, and bilingual.

**Not in your control:** *where* you rank for competitive generic terms ("iOS
developer Riyadh", "hire SwiftUI freelancer"). Those are won with **backlinks and
domain authority over months**, not on-page tags. A portfolio basically won't outrank
companies for those — and that's fine, it's not what it's for.

**Highest-leverage thing you can still do (off-page):** make sure `noiceanas.com` is
linked from your **LinkedIn**, **GitHub profile**, **YouTube channel description**,
and any dev-community profiles. Inbound links from high-authority sites move rankings
far more than anything on the page.

**Realistic timeline:** your own name → top result within days–weeks once re-crawled;
the Arabic result → back within a few weeks after `/index-ar` is indexed; competitive
terms → months, and mostly a function of the backlinks above.
